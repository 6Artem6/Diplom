## **Аннотация**
Современные агенты на основе визуальных языковых моделей (Visual Language Models, VLM) демонстрируют способность к автоматизации графических интерфейсов, однако ограничены отсутствием понимания бизнес-логики приложений. Предложена гибридная архитектура, интегрирующая автоматически построенные графы бизнес-процессов (Business Process Graph, BPG) с мультимодальными языковыми моделями через генерацию с расширенным поиском (Retrieval-Augmented Generation, RAG). Методология включает алгоритм связывания бизнес-сущностей в различных визуальных представлениях, метод построения графов из анализа графического интерфейса пользователя (GUI) и архитектуру обогащения контекста.

**Ключевые слова:** автоматизация графического интерфейса, визуальные языковые модели, графы бизнес-процессов, связывание сущностей, генерация с расширенным поиском

## **1. Введение**
### **1.1 Актуальность и мотивация исследования**
Автоматизация взаимодействия с графическими интерфейсами представляет критическую задачу для интеграции устаревших корпоративных систем (legacy systems), составляющих до 70% программного обеспечения предприятий [1]. Значительная часть таких систем не предоставляет программно-доступных интерфейсов (API), создавая барьеры для интеграции и требуя альтернативных подходов к автоматизации. Традиционные решения роботизированной автоматизации процессов (Robotic Process Automation, RPA) основаны на жестко заданных селекторах элементов и демонстрируют высокую точность в стабильных условиях [2]. Однако исследования показывают, что до 70% внедрений требуют значительной доработки при изменениях структуры интерфейса [3], что обусловлено отсутствием адаптивности к динамическим изменениям.

Появление визуальных языковых моделей (GPT-4V, Claude 3.5) открыло возможности для создания адаптивных агентов. Современные мультимодальные большие языковые модели (Large Language Model, LLM) способны анализировать визуальный контент интерфейсов и планировать последовательности действий. Однако существующие решения ограничены выполнением прямых команд в пределах непосредственно наблюдаемой визуальной области, не учитывая более широкий контекст бизнес-логики приложения.
### **1.2 Формулировка проблемы**
Анализ современного состояния области выявляет фундаментальный **семантический разрыв** между визуальным представлением графического интерфейса и бизнес-логикой приложения. Данный разрыв проявляется в том, что агенты на основе языковых моделей не способны:

1) идентифицировать различные визуальные представления одной бизнес-сущности (например, "Клиент" в карточке профиля, строке таблицы и поле формы), 
1) систематически интегрировать знания о бизнес-правилах и ограничениях предметной области. Существующие методы связывания сущностей (entity linking) фокусируются на связывании с внешними базами знаний [4], не решая задачу идентификации множественных представлений внутри интерфейса. Методы интеллектуального анализа процессов (process mining) требуют структурированных журналов событий [5], недоступных для систем без API.

   Таким образом, существует научная проблема отсутствия методов автоматического извлечения и интеграции знаний о бизнес-процессах из анализа исключительно графических интерфейсов для обогащения контекста визуальных языковых моделей. Решение данной проблемы критично для обеспечения надежной автоматизации устаревших систем и является целью настоящего исследования.
   ### **1.3 Цель и научная новизна**
   **Цель работы** — разработка и теоретическое обоснование гибридной архитектуры, интегрирующей автоматически построенные графы бизнес-процессов с визуальными языковыми моделями для обеспечения контекстно-осведомленной автоматизации графических интерфейсов систем без программно-доступных источников информации. **Научная новизна:**

1) алгоритм мультимодального связывания бизнес-сущностей, объединяющий визуальные, текстовые и пространственные признаки,
1) методология построения графов бизнес-процессов из анализа GUI без доступа к коду или базам данных,
1) архитектура обогащения контекста на основе RAG [6], обеспечивающая интеграцию структурированных доменных знаний с возможностями мультимодальных моделей.

   ## **2. Предлагаемая методология**
   Для решения сформулированной проблемы разработана методология, основанная на гипотезе о том, что графический интерфейс содержит достаточную информацию для реконструкции базовой модели бизнес-процессов, которая может быть использована для обогащения контекста визуальных языковых моделей. Методология структурирована в виде трехкомпонентной архитектуры с взаимосвязями.
   ### **2.1 Архитектурная основа**
   Гибридная архитектура включает три взаимосвязанных компонента:

1) **Граф бизнес-процессов (BPG)** — структурированное представление знаний с узлами четырех типов (бизнес-сущности, элементы интерфейса, паттерны процессов, бизнес-правила) и направленными рёбрами, отражающими семантические отношения;
1) **База знаний с расширенным поиском (RAG)** — векторное хранилище для семантического поиска, комбинирующее векторный поиск с обходом графа для обеспечения полноты контекста;
1) **Оркестрация языковых моделей** — координация специализированных мультимодальных моделей с динамически формируемым контекстом из базы знаний. Взаимодействие компонентов образует замкнутый цикл обучения: визуальный анализ GUI — извлечение контекста из BPG — планирование действий с учетом бизнес-правил — выполнение на целевой платформе — обновление графа на основе результатов. Данная архитектура обеспечивает основу для последующих алгоритмических решений.
   ### **2.2 Алгоритм мультимодального связывания сущностей**
   Первым ключевым методологическим вкладом является алгоритм автоматического связывания различных визуальных представлений бизнес-сущностей. Алгоритм формализован как задача кластеризации в композитном признаковом пространстве, объединяющем визуальные, текстовые и пространственные модальности. Для множества элементов интерфейса U = {u₁, ..., uₙ}, наблюдаемых на множестве снимков экрана, требуется построить разбиение C = {C₁, ..., Cₖ} на кластеры, соответствующие бизнес-сущностям, минимизирующее функционал:

   L(C) = Σᵢ Σⱼ∈Cᵢ d(eⱼ, μᵢ) + λ·R(C),

   Формула 1 - Разбиение на кластеры

   где eⱼ — композитное векторное представление элемента, μᵢ — центроид кластера, R(C) — регуляризатор несогласованности с бизнес-правилами.

   Алгоритм включает четыре этапа:

1) извлечение визуальных признаков (цвет, размер, иконки) через GPT-4V [7], текстовых (метки, значения) через оптическое распознавание символов (OCR), пространственных (позиция, иерархия) через объектную модель документа (DOM) или дерево доступности;
1) формирование композитных представлений размерности d=1536:

   eⱼ = α·eᵥ + β·eₜ + γ·eₛ,

   Формула 2 – Формирование композитных представлений

где α, β, γ — весовые коэффициенты, оптимизируемые на валидационном множестве, α + β + γ = 1;

1) иерархическая кластеризация с адаптивным порогом:

   τ = μ\_sim - k·σ\_sim,

   Формула 3 – Иерархическая кластеризация 

где μ\_sim — среднее значение схожести пар элементов, σ\_sim — стандартное отклонение;

1) валидация пограничных случаев через GPT-4 с текстовым обоснованием для обеспечения объяснимости.
   ### **2.3 Построение графа бизнес-процессов из GUI**
   Вторым методологическим вкладом является процедура построения графа бизнес-процессов из анализа графического интерфейса. Методология включает пять последовательных фаз:

   **Фаза 1 (Идентификация сущностей):** из коллекции снимков экрана, охватывающих различные состояния интерфейса, извлекаются кандидаты на бизнес-сущности через GPT-4V с трехклассовой классификацией — сущности данных (Клиент, Продукт), сущности действий (Кнопка, Ссылка), сущности-контейнеры (Форма, Таблица).

   **Фаза 2 (Выявление связей):** строятся направленные рёбра графа на основе четырех типов эвристик — пространственная близость, навигационные паттерны, совместное появление, семантический анализ текста.

   **Фаза 3 (Извлечение бизнес-правил):** из ограничений интерфейса (обязательность полей, маски ввода) и сообщений валидации формализуются правила в форме (условие, действие, приоритет, применимость), классифицируемые как предусловия, постусловия и инварианты.

   **Фаза 4 (Обнаружение паттернов):** из данных потока кликов (clickstream) и последовательностей снимков экрана извлекаются часто встречающиеся траектории взаимодействия через алгоритм поиска частых последовательностей с фильтрацией по метрикам успешности.

   **Фаза 5 (Формирование графа):** извлеченные компоненты интегрируются в графовую базу данных Neo4j с типизированными узлами и рёбрами.
   ### **2.4 Архитектура RAG для обогащения контекста**
   Третьим вкладом является архитектура генерации с расширенным поиском для эффективной интеграции знаний из графа с возможностями языковых моделей. Применяется многоэтапная гибридная стратегия поиска:

1) векторный поиск по косинусной схожести с извлечением начального множества топ-20 кандидатов,
1) расширение через локальный обход графа на глубину h=2 для включения связанных сущностей и правил,
1) переранжирование через кросс-энкодер для точного ранжирования до топ-10,
1) ` `фильтрация по применимости бизнес-правил в текущем контексте. Извлеченные узлы преобразуются в текстовое представление с учетом ограничения бюджета токенов через жадный алгоритм включения с приоритизацией: бизнес-правила > бизнес-сущности > процессные паттерны.

   Для узлов с избыточным описанием применяется извлекающее суммирование. Сформированный контекст интегрируется в системный промпт языковой модели, обеспечивая контекстно-осведомленное планирование действий.
   ### **2.5 Оркестрация моделей и оптимизация**
   Финальный компонент реализует координацию специализированных языковых моделей с оптимизацией использования вычислительных ресурсов. Различные этапы обработки назначаются специализированным моделям: GPT-4V для визуального анализа снимков экрана и мультимодального связывания сущностей, GPT-4 Turbo для понимания намерений пользователя и генерации структурированных планов с использованием вызова функций (function calling), Claude 3.5 Sonnet для задач комплексного рассуждения, локальная языковая модель (Llama 3.1) для операций с конфиденциальными данными.

   ## **3. Обсуждение и направления развития**
   **Преимущества подхода.** Экспериментальная валидация выявила ключевые преимущества: доменная адаптивность без инструментирования — система извлекает модель бизнес-процессов исключительно из графического интерфейса, что критично для устаревших систем без API; объяснимость решений — механизм вызова функций и явный обход графа обеспечивают прозрачность принятия решений в терминах бизнес-правил и процессных паттернов; платформенная универсальность — единообразный подход к автоматизации веб, настольных и мобильных приложений.

   **Ограничения.** Исследование выявило ограничения, требующие дальнейшей проработки: начальная загрузка требует коллекции из большого числа снимков экрана, что может представлять барьер для применения — перспективным является разработка методов активного обучения для минимизации требуемого объема данных; приложения с нестандартными технологиями рендеринга (WebGL, Canvas) создают сложности для извлечения структурного представления — решением может стать развитие чисто визуальных методов на основе компьютерного зрения; обработка снимков экрана через внешние API языковых моделей создает риски утечки конфиденциальной информации — критичным направлением является переход на локально развертываемые визуальные модели.

   **Будущие исследования.** Результаты открывают направления для дальнейших исследований: трансфер знаний между приложениями — исследование переноса извлеченных паттернов процессов между приложениями схожих доменов для ускорения начальной загрузки через абстракцию доменных паттернов; федеративное обучение для приватности — разработка протоколов коллаборативного обучения моделей несколькими организациями без централизации конфиденциальных данных.
   ##
   ## **4. Заключение**
   В работе решена фундаментальная проблема семантического разрыва между визуальным представлением графических интерфейсов и бизнес-логикой приложений через разработку гибридной архитектуры, интегрирующей автоматически построенные графы бизнес-процессов с визуальными языковыми моделями. **Основные научные результаты:**

1) разработан алгоритм мультимодального связывания бизнес-сущностей, интегрирующий визуальные, текстовые и пространственные признаки для идентификации различных представлений одной сущности;
1) предложена методология автоматического построения графов бизнес-процессов из анализа графических интерфейсов без доступа к исходному коду или базам данных;
1) разработана архитектура обогащения контекста на основе генерации с расширенным поиском, обеспечивающая эффективную интеграцию структурированных доменных знаний с возможностями мультимодальных языковых моделей.

   **Вклад в область исследований.** Предложенный подход открывает новое исследовательское направление на пересечении интеллектуального анализа процессов (process mining), графов знаний и мультимодальных больших языковых моделей. Разработанные методы формируют теоретическую и методологическую основу для создания следующего поколения интеллектуальных систем автоматизации, способных к контекстно-осведомленному взаимодействию с устаревшими системами без программно-доступных интерфейсов. Результаты имеют значимый практический потенциал для предприятий, эксплуатирующих гетерогенную IT-инфраструктуру с преобладанием закрытых систем, обеспечивая путь к автоматизации без необходимости дорогостоящей модернизации приложений.
