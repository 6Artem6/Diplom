# Архитектура восстановления логической структуры UI

Цель: представлять интерфейс как **семантическое дерево**, а не набор несвязанных bounding box'ов. Система должна понимать, где кнопка, что на ней написано, какой текст — заголовок, какой — описание, какой — свободный текст страницы.

---

## 0. Сырая карта UI (Detectron2) — инвариант CV-слоя

Первый шаг — **только геометрия и визуальные типы**, без текста и семантики.

**Инвариант шага Detectron2:**
- Детектирует только визуальные UI-компоненты; работает исключительно с геометрией и внешним видом.
- Не распознаёт текст, не извлекает строки/слова/абзацы; не назначает семантические роли (label, paragraph, title и т.п.); не агрегирует layout и не группирует элементы в регионы.
- Если элемент визуально кнопка с надписью — результатом является только bbox кнопки, без текста внутри.

**Допустимый выход CV-слоя (только эти поля):**
- `id` — уникальный идентификатор атома
- `source` = `"detectron2"`
- `type` — button, card, input, navbar, container, icon, checkbox, radio, dropdown, modal, text_block, unknown
- `bbox` — [x1, y1, x2, y2]
- `confidence`

**Запрещены на этом шаге:** text, role, paragraph, label, lines_count, region_id, объединённые текстовые блоки. Наличие этих полей = нарушение архитектуры. Текст всегда живёт отдельно (OCR) и привязывается позже (Merge).

Модель контракта: `RawUICVAtom` в `src/domain/models/ui_structure.py` (Pydantic, `extra = "forbid"`).

---

## 1. Разделение ответственности

| Слой | Ответственность | Не делает |
|------|-----------------|-----------|
| **CV (Detectron2)** | Геометрия и типы UI-элементов: кнопки, поля ввода, карточки, navbar, контейнеры | Не источник текста, не классификация текста |
| **OCR** | Единственный источник текста. Полностранично, независимо от CV | Не определяет типы UI |
| **Merge** | Геометрическое связывание текста и UI (IoU / покрытие) | Не интерпретирует семантику текста |
| **Semantic** | Логические роли текста: заголовок, описание, CTA, подпись и т.п. (например LayoutLM3) | Не строит геометрию, не детектирует боксы |

Текст и UI-элементы **не блокируют друг друга**: даже если CV нашёл кнопку или input, OCR всё равно видит текст внутри этих областей. Связывание — отдельный логический слой.

## 2. Форматы данных

### 2.1 UI Atom (выход CV-слоя — сырая карта UI)

- **Строгий формат (инвариант)**: `RawUICVAtom` — только `id`, `source` = "detectron2", `type`, `bbox` [x1,y1,x2,y2], `confidence`. Любые другие поля запрещены.
- **Типы**: button, card, input, navbar, container, icon, checkbox, radio, dropdown, modal, text_block, unknown.
- **Источник**: только CV-модель (например Detectron2). Текст и семантика текста не входят в этот слой.

### 2.2 Raw OCR Box (выход OCR-слоя — сырой OCR)

- **Строгий формат (инвариант)**: `RawOCRBox` — только `id`, `source` = "ocr", `bbox` [x1,y1,x2,y2], `text`, `confidence`. Любые другие поля запрещены.
- **Запрещены на этом шаге**: role, paragraph, lines_count, region_id, label, type, semantic_role. OCR ничего не знает про UI, регионы, кнопки, карточки.
- **Источник**: только OCR (полностранично, независимо от CV). При `parallel_ocr=true` результат всегда возвращается как `raw_ocr_boxes` и отображается в debug-визуализации.
- **Контракт**: `legacy_text_pipeline=false` → только `raw_ocr_boxes` (нет строк, абзацев, зелёных боксов). Detectron2 никогда не создаёт текст. OCR никогда не создаёт UI-типы.

### 2.3 Bbox

- **BboxXYXY**: `[x1, y1, x2, y2]` в координатах изображения.
- **BboxXYWH**: `x, y, width, height`.
- Конвертация между форматами — в доменных моделях (`ui_structure.py`).

## 3. Правила геометрического связывания (Merge)

Связывание текста и UI — **только по геометрии** (IoU / покрытие), не по эвристике типов.

### 3.1 Метрика

- **Coverage ratio** для пары (OCR-бокс, UI-атом):  
  `coverage = area(intersection(ocr_box, atom_bbox)) / area(ocr_box)`  
  т.е. доля площади текстового бокса, попадающая внутрь bbox атома.

### 3.2 Правила

1. **Порог привязки**: если `coverage >= threshold` (например 0.5), OCR-бокс считается привязанным к атому.
2. **Доминирующий атом**: при пересечении с несколькими атомами выбирается атом с максимальным `coverage`; при равенстве — с меньшей площадью (более специфичный контейнер).
3. **Тип связи**:
   - `label` — текст как подпись элемента (кнопка, поле);
   - `content` — текст как содержимое элемента (поле ввода, карточка);
   - `standalone` — текст не привязан к одному элементу или вне UI.
4. **Текст не удаляется из общего слоя**: привязка к элементу добавляет связь `TextUILink`, но OCR-бокс остаётся в общем текстовом слое (строки, абзацы, независимые блоки).

### 3.3 link_type (эвристика, без ML)

- **button, input, title, navbar, icon, dropdown, checkbox, radio** → `label`.
- **card, container, text_block, modal, unknown** → `content`.
- Это не финальная семантика, а первичная привязка для UI-дерева и последующих слоёв (LayoutLMv3, правила, LLM).

### 3.4 Выход Merge Layer v2

- Список `TextUILink`: `ocr_box_id`, `atom_id` (None = standalone), `link_type`, `coverage_ratio`. Модель с `extra = "forbid"`.
- Атомы и `raw_ocr_boxes` не модифицируются; связь не удаляет и не перемещает текст.
- По связям строится `text_inside_ui` для `_build_logical_ui` (подписи кнопок, контент карточек). Текст вне UI сохраняется (standalone).

---

## 4. Семантический слой (опционально)

- **Вход**: OCR-боксы + координаты + привязка к UI-элементам (из Merge).
- **Выход**: роли текста — `TextSemanticRole` (title, description, caption, cta, body, label, placeholder, free_text, unknown).
- **Не входит в CV**: классификация «заголовок / описание / CTA» — задача отдельной модели (например LayoutLM3), работающей с текстом и layout, а не с сырым изображением детекции.

---

## 5. Итоговое семантическое дерево (UINode)

- Узел: `type`, `bbox`, `label` (подпись из связанного текста), `text_content` (весь привязанный текст), `semantic_roles`, `children`.
- Кнопки имеют корректные подписи; карточки — заголовки и тело; текст вне UI не теряется; input'ы не «пожирают» обычный текст.
- Результат пригоден для анализа, экспорта, автогенерации интерфейса.

---

## 6. Слоистая архитектура (схема)

```
[Изображение]
      │
      ├──► CV-слой (сырая карта UI)  → UIAtom[] (геометрия + визуальный тип, без текста)
      │
      └──► OCR-слой       → OCRBox[] (текст, полностранично)
                │
                ▼
           Merge-слой      → TextUILink[] (связь по IoU/покрытию)
                │
                ├──► Текстовый слой (все OCR-боксы: строки, абзацы, независимые блоки)
                │
                └──► Построение дерева UINode (атомы + привязанный текст)
                            │
                            ▼
                     Semantic-слой (опц.) → TextSemanticAnnotation[] (роли текста)
                            │
                            ▼
                     Финальное дерево UINode с ролями
```

Каждый слой **отключаем и заменяем** без переписывания всего пайплайна (интерфейсы в `src/domain/interfaces/ui_structure_layers.py`).
